# 实现任务拆分清单 v1（不改代码版）

## 1. 目标

基于以下两份文档，形成可直接执行的开发清单：

- `股票分析算法/规则映射表_v1.md`
- `股票分析算法/字段接口草案_v1.md`

本清单覆盖：

- 修改文件
- 新增函数
- 输入输出约定
- 验收条件
- 风险与回滚点

## 2. 总体里程碑

- M1：规则引擎核心计算可用（无 UI）
- M2：上下文接入 AI 投顾链路
- M3：前端展示与文案约束打通
- M4：样本回放与阈值校准

## 3. 任务分解（按阶段）

### 阶段 A：规则引擎实现（核心）

#### A1. 新增模块骨架

- 文件：`stock_analysis/analysis/trend_signal.py`
- 任务：
  - 新建 `TrendSignalConfig`（参数容器）
  - 新建 `analyze_trend_signal(...)` 主入口
  - 定义统一输出结构（`schema_version=trend_signal_output_v1`）
- 验收：
  - 函数可在最小样本上返回完整结构（允许部分值为 `null`）
  - 不抛未捕获异常

#### A2. 输入标准化与校验

- 文件：`stock_analysis/analysis/trend_signal.py`
- 新增函数建议：
  - `_normalize_daily_df(df: pd.DataFrame) -> pd.DataFrame`
  - `_validate_daily_df(df: pd.DataFrame) -> list[str]`
- 要点：
  - 统一列名：`date/open/high/low/close/volume/amount`
  - 数值化、排序、剔除非法行
  - 输出 `quality.warnings`
- 验收：
  - 非升序输入可自动纠正
  - 缺失列时给出明确 warning

#### A3. 指标计算层

- 文件：`stock_analysis/analysis/trend_signal.py`
- 新增函数建议：
  - `_calc_mas(df) -> dict`
  - `_calc_bias(price, ma5, ma10, ma20) -> dict`
  - `_calc_volume_ratio_5d(df) -> float | None`
  - `_calc_macd(df, fast=12, slow=26, signal=9) -> dict`
  - `_calc_rsi(df, periods=(6,12,24)) -> dict`
- 验收：
  - 输出字段满足 `字段接口草案_v1`
  - 边界样本（<20 根）可降级返回

#### A4. 规则分类层

- 文件：`stock_analysis/analysis/trend_signal.py`
- 新增函数建议：
  - `_classify_ma_alignment(df, ma5, ma10, ma20) -> tuple[str, str, int]`
  - `_classify_volume_status(volume_ratio_5d, price_change_pct_1d) -> tuple[str, str]`
  - `_detect_support_resistance(df, price, ma5, ma10, ma20, tolerance=0.02) -> dict`
  - `_classify_macd_status(macd_dict) -> tuple[str, str]`
  - `_classify_rsi_status(rsi_dict) -> tuple[str, str]`
- 验收：
  - 枚举值严格来自草案
  - 关键阈值（5%、1.5、0.7、2%）生效

#### A5. 评分与信号层

- 文件：`stock_analysis/analysis/trend_signal.py`
- 新增函数建议：
  - `_score_trend(...) -> int`
  - `_score_bias(...) -> int`
  - `_score_volume(...) -> int`
  - `_score_support(...) -> int`
  - `_score_macd(...) -> int`
  - `_score_rsi(...) -> int`
  - `_compose_signal(score, trend_type) -> str`
  - `_build_reasons_and_risks(...) -> tuple[list[str], list[str]]`
- 验收：
  - `signal_score` 范围 `0-100`
  - `buy_signal` 分档符合 v1 规则

### 阶段 B：与现有上下文集成

#### B1. 构建入口接入

- 文件：`stock_analysis/ui/future_features.py`
- 变更点：`_build_context(...)`
- 任务：
  - 在日线数据准备完后调用 `analyze_trend_signal(...)`
  - 将结果挂到 `context["trend_signal"]`
  - 保留现有 `daily_trend` 与 `price_range_analysis`
- 验收：
  - `st.session_state` 有数据时，`context` 始终含 `trend_signal`（至少空壳+warning）

#### B2. 可读摘要层补充

- 文件：`stock_analysis/ui/future_features.py`
- 变更点：`_build_readable_summary(...)`
- 任务：
  - 增加“规则引擎摘要”段落
  - 包含：量比、MA 支撑/压制、排列状态、评分
- 验收：
  - 摘要可覆盖你要的句式要点

### 阶段 C：Prompt 与输出约束

#### C1. Prompt 约束增强

- 文件：`stock_analysis/ui/future_features.py`
- 变更点：`_build_prompts(...)`
- 任务：
  - 新增规则：事实段优先引用 `trend_signal`
  - 新增规则：每条核心判断必须附数值
  - 新增规则：`quality.data_sufficiency != high` 时明确“依据不足”
- 验收：
  - LLM 结果中不再混用“日线 MA”和“分钟 MA”

#### C2. AI 结果展示校验

- 文件：`stock_analysis/ui/future_features.py`
- 任务：
  - 增加调试预览（可折叠）显示 `trend_signal`
- 验收：
  - 页面可直接核对规则结果与文案一致性

### 阶段 D：测试与回放

#### D1. 单元测试

- 新增文件：`tests/test_trend_signal.py`
- 覆盖点：
  - MA 分类
  - 乖离率阈值
  - 量比分类
  - 支撑判定
  - 评分分档
  - 异常输入降级
- 验收：
  - 关键逻辑分支全部命中

#### D2. 场景回放测试

- 新增文件：`tests/test_trend_signal_regression.py`
- 任务：
  - 准备 20-30 个样本（多头、空头、震荡、放量反弹、放量下跌）
  - 固化预期枚举字段，不强绑文案
- 验收：
  - 回放结果稳定，无随机漂移

## 4. 文件级改动清单（汇总）

- 新增：`stock_analysis/analysis/trend_signal.py`

## 5. 验收清单（Definition of Done）

- 功能验收：
  - 对任一股票可产出 `trend_signal` 完整结构
  - 能稳定表达“放量/缩量 + MA 支撑压制 + 排列状态 + 评分结论”
- 一致性验收：
  - 同样输入重复运行结果一致
- 口径验收：
  - 日线与分钟口径严格区分
- 质量验收：
  - 数据不足时降级而非胡乱结论
- 测试验收：
  - 单测与回放测试可通过

## 6. 推荐执行顺序（开发节奏）

1. 先做阶段 A（纯算法，不碰 UI）
2. 再做阶段 B（只接 context，不改 prompt）
3. 再做阶段 C（收敛文案输出）
4. 最后做阶段 D（回放校准与回归）

## 7. 工时估算（1 人）

- 阶段 A：2-3 天
- 阶段 B：1 天
- 阶段 C：1 天
- 阶段 D：2-4 天
- 合计：6-9 天

## 8. 风险与回滚点

- 风险 1：量比数据源口径漂移
  - 处理：统一使用日线推导 `volume_ratio_5d`
- 风险 2：评分规则导致结论过度激进
  - 处理：先保守阈值，回放后再调
- 风险 3：AI 生成覆盖规则事实
  - 处理：Prompt 强约束 + 调试面板核对
- 回滚点：
  - 若上线后效果不稳定，可仅保留 `trend_signal` 计算，不对 AI 文案启用强依赖
