# 字段接口草案 v1（Trend Signal Engine）

## 1. 目标

定义“规则引擎层”的标准输入/输出接口，确保：

- 规则计算可复现（脱离 LLM 也能稳定产出）
- 与当前项目 `AI 投顾` 上下文可直接对接
- 后续阈值迭代不破坏上层调用

本草案与 `股票分析算法/规则映射表_v1.md` 一致。

## 2. 模块边界

建议新增模块：`stock_analysis/analysis/trend_signal.py`

建议核心函数签名：

```python
analyze_trend_signal(
    daily_df: pd.DataFrame,
    stock_meta: dict,
    as_of_date: str | None = None,
    config: dict | None = None,
) -> dict
```

- `daily_df`：日线 OHLCV（升序）
- `stock_meta`：`code/name/source` 等元信息
- `as_of_date`：分析日期（可选，不传则使用最新行日期）
- `config`：阈值参数（可选，默认加载 v1 基线）

## 3. 输入接口（JSON 结构）

> 说明：函数内部可接受 DataFrame；这里给出标准化 JSON 形态，便于 API/测试复用。

### 3.1 Input Schema（逻辑）

```json
{
  "schema_version": "trend_signal_input_v1",
  "stock": {
    "code": "601899",
    "name": "紫金矿业",
    "market": "CN-A"
  },
  "data_scope": {
    "as_of_date": "2026-02-09",
    "timezone": "Asia/Shanghai",
    "source": "akshare|tushare|mixed"
  },
  "daily_ohlcv": [
    {
      "date": "2026-01-02",
      "open": 16.83,
      "high": 17.12,
      "low": 16.70,
      "close": 17.01,
      "volume": 123456789,
      "amount": 2100000000
    }
  ],
  "config_override": {
    "bias_threshold_pct": 5.0,
    "ma_support_tolerance": 0.02,
    "volume_shrink_ratio": 0.7,
    "volume_heavy_ratio": 1.5
  }
}
```

### 3.2 必填/可选字段

- 必填：
  - `stock.code`
  - `daily_ohlcv[].date/open/high/low/close/volume`
- 可选：
  - `stock.name/market`
  - `daily_ohlcv[].amount`
  - `data_scope.*`
  - `config_override.*`

### 3.3 输入校验规则

- `daily_ohlcv` 至少 20 条：
  - `<20`：允许返回，但必须标记 `quality.data_sufficiency = "low"`
- `date` 可解析为日期，且整体升序（若非升序，内部先排序）
- `open/high/low/close/volume` 必须为数值；无效值剔除
- `volume >= 0`，`high >= low`，`close > 0`

## 5. 输出字段定义与枚举

### 5.1 枚举字段

- `ma_alignment_type`：
  - `strong_bull`
  - `bull`
  - `weak_bull`
  - `consolidation`
  - `weak_bear`
  - `bear`
  - `strong_bear`

- `volume_status`：
  - `heavy_up`
  - `heavy_down`
  - `shrink_up`
  - `shrink_down`
  - `normal`

- `macd_status`：
  - `golden_cross_zero`
  - `crossing_up`
  - `golden_cross`
  - `death_cross`
  - `crossing_down`
  - `bullish`
  - `bearish`

- `rsi_status`：
  - `overbought`
  - `strong_buy_zone`
  - `neutral`
  - `weak`
  - `oversold`

- `buy_signal`：
  - `strong_buy`
  - `buy`
  - `hold`
  - `wait`
  - `sell`
  - `strong_sell`

- `quality.data_sufficiency`：
  - `high`
  - `medium`
  - `low`

### 5.2 数值字段单位

- 价格类：元（`float`）
- 百分比类：`_pct` 后缀字段统一为 `%`
- 量比：无单位（倍数）
- 评分：`0-100` 整数

## 6. 配置接口（阈值参数）

### 6.1 Config Schema（逻辑）

```json
{
  "schema_version": "trend_signal_config_v1",
  "bias_threshold_pct": 5.0,
  "ma_support_tolerance": 0.02,
  "volume_shrink_ratio": 0.7,
  "volume_heavy_ratio": 1.5,
  "macd": {
    "fast": 12,
    "slow": 26,
    "signal": 9
  },
  "rsi": {
    "short": 6,
    "mid": 12,
    "long": 24,
    "overbought": 70,
    "oversold": 30
  },
  "score_weights": {
    "trend": 30,
    "bias": 20,
    "volume": 15,
    "support": 10,
    "macd": 15,
    "rsi": 10
  }
}
```

### 6.2 校验规则

- 所有阈值需为正数
- `score_weights` 总和必须为 `100`
- `macd.fast < macd.slow`
- `rsi.short < rsi.mid < rsi.long`

## 7. 与当前项目上下文对接规范

当前项目建议在 `context` 内新增：

```json
{
  "trend_signal": { "...见 4.1..." }
}
```

### 7.1 与现有字段的关系

- `daily_trend`：保留（基础趋势快照）
- `trend_signal`：新增（规则引擎结果，供 AI 直接引用）
- `price_range_analysis`：保留（区间法，与 MA 支撑压制互补）

### 7.2 Prompt 约束建议（后续接入）

- 事实段优先引用 `trend_signal`，每条结论附数值
- 当 `quality.data_sufficiency != high` 时，必须输出“依据不足”
- 不得把 `minute_ma*` 当成 `daily_ma*` 使用

## 8. 错误与降级返回规范

### 8.1 错误场景

- 日线数据为空
- 数据全为 NaN 或无法解析

### 8.2 返回约定

- 不抛出未捕获异常到上层 UI
- 返回结构不变，但 `trend_signal` 可为空对象
- `quality.warnings` 给出错误说明，例如：

```json
{
  "quality": {
    "data_sufficiency": "low",
    "warnings": ["daily_ohlcv length < 20", "MACD not ready"]
  }
}
```

## 9. 最小测试向量（接口级）

- Case A：60 日完整数据，多头趋势 + 放量上涨
- Case B：30 日数据，均线缠绕 + 正常量
- Case C：25 日数据，空头排列 + 放量下跌
- Case D：不足 20 日，检查降级返回
- Case E：异常值（负 volume、无 close），检查容错

## 10. 版本策略

- 当前版本：`v1`
- 向后兼容原则：
  - 新增字段可选
  - 已有字段不改名、不改语义
- 版本升级触发条件：
  - 字段语义变化
  - 枚举值变化
  - 评分体系权重结构变化
